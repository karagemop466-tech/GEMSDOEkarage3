## Scientific premise

The target is a **fault-confidence map**, not a direct geothermal-vent detector. The organizer's [problem description](https://www.drivendata.org/competitions/306/competition-doe-gems/page/967/) describes hidden, expert-labeled faults. In the [Southern Gabbs Valley study](https://pubs.usgs.gov/publication/70201803), geophysics, structure and temperatures supported a blind geothermal system without a surface hot spring; this is evidence for multi-source exploration, not evidence that a particular grid anomaly is a fault or vent.

### Relative improvement estimates—not measurements

These are **qualitative, speculative rankings**, not HOLDOUT-DTI values or projections of organizer scores. There is no defensible numerical improvement estimate without a matched holdout. (1) MSP-Offset: highest potential of this slate, moderate cost, because complementary gravity/magnetic offsets may carry information under cover. (2) Drainage-reversal: medium potential, high cost, conditional on adequate terrain/hydrography coverage and repeated stream crossings. (3) Matched temperature: medium-to-low potential, moderate–high cost, limited by sparse and biased probing. (4) Radiometric residual: uncertain-to-low potential, moderate–high cost, because surface alteration and acquisition effects may not correlate with the hidden labels. Any ranking may reverse under a leak-free holdout.

## Future validation plan (only after assignment / protocol resolution)

1. Pin the assigned lane, input licenses, full registry and comparable incumbent before viewing outcomes. Record exact commits/hashes and a three-experiment/two-hour budget. Do not tune a dot budget merely to avoid the lattice.
2. Hide **whole fault segments**, spatially block folds, and buffer separation. Rebuild every catalogue-dependent feature, sampling mask and emitter from **visible faults only** per fold. Mask visible faults pixel-exactly in evaluation, as [staff clarified](https://community.drivendata.org/t/scoring-clarification-are-known-usgs-ingenious-faults-masked-when-scoring-and-are-they-in-the-final-round-label-set/11516/4). A single model built from the full catalogue then retrospectively masked is not a leakage-safe test.
3. Test each feature alone before model training. Report per-fold direction-aware AUC and investigate any AUC >0.90 as leakage until disproved. Probe fold generation as well as feature values; negatives can contain unmapped positives.
4. Use the shared, pinned template evaluator for pooled distance-weighted Tversky, α=0.2, β=0.8 and a 300 m triangular kernel. Compare candidate and current best on identical folds and report withheld-positive count and spatial-block paired 95% interval. Lock a confirmation split; a proxy DTI is not a calibrated leaderboard score.
5. Measure pre-placement surface rank correlation and final-dot proximity against **every** currently registered raster, including controls under the literal rule. Undefined correlation, missing files or incomplete registry mean stop, not pass.
6. Reopen and audit the exact saved GeoTIFF; test the outside-mask convention separately from the whole-array range diagnostic. A format result does not establish scientific success or organizer acceptance. A separate selector considers quota and eligibility only after all gates pass.

## Critical implementation irregularity

At pinned GEMSDOE32 commit [`73485f27`](https://github.com/buffedlizard55-lab/GEMSDOE32/tree/73485f27cf230af770167397c2b72cb9ce3b3f25), the local [`scripts/submission_writer.py`](https://github.com/buffedlizard55-lab/GEMSDOE32/blob/73485f27cf230af770167397c2b72cb9ce3b3f25/scripts/submission_writer.py#L68-L70) thresholds every positive input to a boolean despite accepting `mask_or_probs`. Its [`scripts/evaluate_holdout.py`](https://github.com/buffedlizard55-lab/GEMSDOE32/blob/73485f27cf230af770167397c2b72cb9ce3b3f25/scripts/evaluate_holdout.py#L38-L56) does the same for TIFF/NPY and casts NPZ values to bool. This changes continuous probabilities and can hide invalid inputs; binary-only valid masks are a narrower case. The underlying [`vendor/gems57/evaluate_holdout.py`](https://github.com/buffedlizard55-lab/GEMSDOE32/blob/73485f27cf230af770167397c2b72cb9ce3b3f25/vendor/gems57/evaluate_holdout.py) handles finite continuous predictions. [Upstream issue #37](https://github.com/buffedlizard55-lab/GEMSDOE32/issues/37) already reports the defect. We have read-only permissions on that repository, so no private evaluator/writer fork or unsupported claim of a fix was made. Future runs must use the shared template and either fix the shared wrappers upstream or have them explicitly reject nonbinary inputs.
