A defensible metric explanation

The protocol uses distance-tolerant coverage and weights false negatives more heavily than false positives. A dense line can spend many predictions covering nearly the same neighborhood. Sparse placements can retain much of that coverage with less redundant prediction mass. Removing low-credit predictions near known traces can therefore improve the precision–coverage tradeoff if withheld-fault coverage is retained.

This is a conditional mechanism, not evidence that the hidden organizer labels reward these specific deletions. Catalogue-adjacent unknown faults may also be real: an exclusion buffer can discard true positives. A controlled, fold-local ablation is required to measure the net effect. Reusing a full-catalogue-pruned pattern as a hide-and-recover candidate would not establish leakage-free discovery.

The official reference notebook verifies its training loss weights α=0.2 and β=0.8. Why none of these is a new eligible submission

All nine historical files pass the shared, unchanged saved-byte validator in all-finite mode against a hash-pinned owner-mirrored template: one float32 band, matching CRS/shape/transform, finite values in [0,1], and no positive predictions on catalogue traces. This does not authenticate the template with the organizer or guarantee portal acceptance.

Every historical file nevertheless has more than 70% of its dots within three pixels of another audited file. Under the literal parallel-run rule, that is an automatic duplicate stop. We did not exempt dense references or calibration rasters. The partial comparison set is sufficient to demonstrate these failures, but cannot certify a new file against the complete registry. Continuous-surface checks were not possible from final-dot TIFFs.
