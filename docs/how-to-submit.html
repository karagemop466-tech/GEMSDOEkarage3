1. What the official rules require

Quoted from the official problem page (DrivenData, Submission format, retrieved 2026-10-30):

  • Projected CRS EPSG 32611 (UTM zone 11N), 100 m resolution, same bounds as the training data.
  • “data outside the bounds is null or nan.”
  • Single layer, datatype 32-bit float (float32), values between 0 and 1.

The official rules are at docs.nlr.gov/docs/fy26osti/96647.pdf.

3. Step-by-step: how to submit once a file is cleared

  1. Choose only a file marked OK to submit: YES. Today there is none on this project.
  2. Open DrivenData GEMS (#306). Go to DrivenData DOE GEMS Competition, sign in, and navigate to the Submissions page.
  3. Upload the file. Select the approved single-band GeoTIFF (or a .zip containing exactly one GeoTIFF). Use an all-finite variant (values in [0,1], zero NaN) to avoid the "Predicted values must be in range [0, 1]" rejection; never upload a -nan.tif.
  4. Enter a unique submission name and a note (≤140 characters) to tell submissions apart.
  5. Save the organizer receipt. Record the DrivenData submission-page confirmation binding filename, SHA-256, timestamp and returned score. Only receipt-backed scores may be labeled ORGANIZER-CONFIRMED.
  6. Select one final submission. Public feedback is not the private or final score; do not spend a slot merely because a file is downloadable.

4. Open conflict: NaN versus 0.0 outside the footprint

  • -nan.tif: NaN outside the footprint. Matches the official “null or nan” wording. The user-reported portal error “Predicted values must be in range [0, 1]” was seen with a file of this kind (the exact file was not recorded). The cause of that error is unexplained.
  • -zeros.tif: 0.0 outside the footprint. Does not match the official “null or nan” wording. Earlier notes recommended this variant; that recommendation is withdrawn until the organizer confirms it.

Resolving this needs an organizer answer (the DrivenData user forum, linked from the problem page), not a guess.
