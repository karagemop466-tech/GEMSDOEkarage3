1. What the official rules require (verified on the problem page)

Quoted from the official problem description (DrivenData GEMS · Submission format, retrieved 2026-10-31):

  • Single-band GeoTIFF in EPSG:32611 (UTM zone 11N), 100 m resolution, same bounds as the training data; “data outside the bounds is null or nan”.
  • Datatype float32; values between 0 and 1 (higher = more confident fault presence).
  • You may upload a single-band GeoTIFF (.tif) or a .zip containing one GeoTIFF.
  • Add a short Note (≤ 140 chars) to tell submissions apart, e.g. “clustering with k=25”.

Official rules PDF: docs.nlr.gov/docs/fy26osti/96647.pdf.

2. The two file variants this repository writes (and when to use each)

1

-zeros.tif (PRIMARY)

0.0 outside the footprint, no nodata tag, all 12,279,160 cells finite in [0, 1]. This variant cannot trigger the portal error “Predicted values must be in range [0, 1]” (NaN fails a strict range check), and it matches the official float32/[0,1] rule. Reported receipts exist for this variant (e.g. GEMSDOE32 0.2778).

2

-nan.tif (FALLBACK)

NaN outside the footprint with nodata=NaN — the literal reading of “data outside the bounds is null or nan”. Reported receipts also exist for this variant (e.g. GEMSDOE28 0.2710). Use it only if the portal ever rejects the -zeros file.

3. Step by step (the day a file is cleared)

  1. Open the cleared file's link on the overview release card and download the -zeros.tif (or its .zip).
  2. Log in at DrivenData · DOE GEMS (#306) and open New submission.
  3. File to submit: choose the downloaded .tif (or .zip).
  4. Note: paste the exact submission note printed on the file's run card (≤ 140 characters; it names the method, dot count and gate status so future-you can tell submissions apart).
  5. Submit. The site scores it on the public test chunk; the Initial Prize Round is scored on the private chunk at close.
  6. Record the returned score + submission name in the repo ledger so the calibration (PROJECTION → receipt) improves every session.

Weekly cap: promotion to a real slot is a separate selector step within the weekly cap shown on the submission page — never an automatic consequence of a green gate.

4. If the portal returns “Predicted values must be in range [0, 1]”

  • You almost certainly uploaded a NaN-carrying file (or an all-NaN/wrong-grid file). Use the -zeros.tif variant: every cell is finite and inside [0, 1], so a strict range check cannot fail.
  • Verify the file matches the template grid (3730 × 3292, EPSG:32611, 100 m) — the repository's writer already guarantees this; a re-saved or re-exported copy (e.g. opened in GIS and re-exported) can silently change dtype/CRS, so always upload the pristine downloaded bytes.
  • If the portal rejects the -zeros file for “null or nan outside bounds”, use the -nan.tif twin — both variants are written for exactly this ambiguity, which is a standing owner question.
