How to submit after a future approval

These steps apply only after the dashboard explicitly shows OK TO DOWNLOAD AND SUBMIT: YES, the file hash matches its passing run card, and a separate selector approves the slot. None of those conditions is currently met.

  1. Download only the exact `.tif` or single-TIFF `.zip` linked from the approved candidate card. Do not use a historical or quarantined file.
  2. Verify the exact saved bytes: one-band GeoTIFF; EPSG:32611; competition grid shape and transform; predictions within [0, 1]; no NaN or infinity in the submission array; required outside-footprint convention; SHA-256 matches the run card.
  3. On the official DrivenData submission page, upload the file and use the unique submission name and short note (at most 140 characters) from the approved card.
  4. Save the organizer receipt with filename, hash, timestamp and returned score. Only that artifact-bound receipt may be labeled ORGANIZER-CONFIRMED.

The repository's automated validator and selector are intended to remove manual inspection from the scientific and format gates. The final upload and any account-specific slot action still occur on the organizer's site and cannot be represented as completed without a receipt.

About the range error

The message “Predicted values must be in range [0, 1]” establishes that the submitted values were rejected by a range validation. It does not, by itself, identify whether NaN, infinity, out-of-range values, or another serialization detail caused the rejection. Validate the exact file that was uploaded—not a similarly named sibling—and record its SHA-256. No current candidate has been cleared for upload in response to that earlier error.
