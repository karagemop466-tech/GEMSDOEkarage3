How to submit to DOE GEMS — and why nothing is cleared yet

OK to download and submit? NO. No file in this repository has passed every gate. This page replaces an earlier version that wrongly described karage3-unique-offcat as ready to upload.

Why karage3-unique-offcat is NOT OK to submit

  1. Outside-footprint dots. 7,483 of its 12,000 positive pixels (62.4%) lie outside the 5,167,373-cell study footprint, where the organizer's own sample submission is NaN (the sample has 60,988 positive pixels, all inside it). The file writes 1.0 there, and the -zeros version writes 0.0 instead of null everywhere else. Null-outside is the organizer's example convention; the official page only says "data outside the bounds is null or nan".
  2. The lattice pass depends on those dots. Counting only dots inside the footprint, 99.89% lie within 3 px of the registered calibration lattice (limit 70%). Counting all 12,000 dots, 37.65% do, but only because the outside dots are far from the lattice.
  3. The -nan file is not a NaN file. Its pixel values equal the -zeros file exactly; only the nodata tag differs. It contains zero NaN pixels.
  4. Not checked. Rank correlation against every registry raster, the complete registry, and the organizer's acceptance of out-of-footprint values have not been checked. No holdout score exists for this detector.

Measured by scripts/lattice_feasibility.py and scripts/audit_saved_tiffs.py (receipts in evidence/). Source metadata: official problem and submission format page.

Steps for a future submission (only after every gate passes)

  1. Produce a candidate in the shared template's grid: EPSG:32611, 3730 × 3292, 100 m, one float32 band, values in [0, 1], and the same null convention as the organizer sample outside the footprint.
  2. Run the automated checks (no human visual check substitutes): scripts/check_submission.py FILE.tif --strict-finite, scripts/lattice_feasibility.py, scripts/audit_saved_tiffs.py, and the registry scan. Each must PASS on the saved bytes.
  3. Record the lattice overlap under both readings: footprint-restricted and all positive pixels. A file that passes only one reading is not cleared.
  4. Get a selector decision that checks the weekly cap on the DrivenData submission page. Until then, do not upload.
  5. Upload the single .tif (or a .zip containing one .tif) with a unique name and a note of 140 characters or fewer, and record the portal's response in a receipt.
