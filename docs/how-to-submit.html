1. What the official rules require

Quoted from the official problem page (DrivenData, Submission format, retrieved 2026-10-30):

  • Projected CRS EPSG 32611 (UTM zone 11N), 100 m resolution, same bounds as the training data.
  • “data outside the bounds is null or nan.”
  • Single layer, datatype 32-bit float (float32), values between 0 and 1.

The official rules are at docs.nlr.gov/docs/fy26osti/96647.pdf.

2. Open conflict (not resolved)

The repository holds two variants of each candidate. Neither has an organizer receipt.

  • -nan.tif: NaN outside the footprint. This matches the official “null or nan” wording. The user-reported portal error “Predicted values must be in range [0, 1]” was seen with a file of this kind (the exact file was not recorded). The cause of that error is unexplained.
  • -zeros.tif: 0.0 outside the footprint. This does not match the official “null or nan” wording. Earlier notes recommended this variant; that recommendation is withdrawn until the organizer confirms it.

Resolving this needs an organizer answer (the DrivenData user forum, linked from the problem page), not a guess.
