What a compliant submission must pass before anyone uploads it

  1. Literal uniqueness. Measure in-footprint 3-px overlap against every registered raster, both on the surface and on final dots. Stop if more than 70% of dots overlap any one raster, or if rank correlation exceeds 0.90. The current registry includes a 206,895-dot lattice that covers 99.87% of the footprint, so any footprint-internal dot file must place at least 30% of its dots in the 6,649 cells the lattice does not cover. Almost all of those cells are the boundary ring (6,580 of 6,649). That is a geometric loophole, not a geological signal. The project has not resolved this rule; see the owner decision in the README.
  2. Format. One float32 band, EPSG:32611, 3730 × 3292, transform (100, 0, 243350, 0, −100, 4508550). Values in [0, 1] inside the footprint. No NaN inside the footprint. Outside-footprint convention must match the official template, which is not verified here. The repo's strict validator fails positive dots outside the footprint; how the portal treats them is unverified.
  3. Holdout. A new candidate must beat the same-holdout champion on a valid spatially blocked holdout. This has not been run for any new candidate.
  4. Human-free validation. Every check must run without manual input and emit a machine-readable receipt.
  5. Note. A unique name and a comment of at most 140 characters, recorded with the submission receipt.

When all five pass and the owner has resolved the uniqueness rule in writing, rebuild the pages with scripts/build_site.py, which will then render the download. Until then the download is intentionally disabled.
