## 4. The uniqueness rule and the lattice (reproduced today)

The rule (AGENTS.md): a candidate is a duplicate if more than **70 %** of its dots lie within **3 px** of any registered raster's dots. The rule is applied before placement and on the final dots.

Reproduced from the pinned witness (`13GEMSDOE r13-lattice-s5`, SHA-256 `b4570b40…`, which matches the pin). Script: `scripts.verify_lattice_bound.run()`. All five fields match [evidence/lattice-bound-20261030.json](../evidence/lattice-bound-20261030.json):

| Lattice dots | 206,895 |
| Footprint cells within 3 px of a lattice dot | 99.8713 % |

| Largest support that can meet ≤ 70 % | **22,163 cells** |

Hand check of the arithmetic:
- (37,654 − 6,649) / 37,654 = **0.8234** → violates the rule.
- (22,163 − 6,649) / 22,163 = **0.69998** → meets the rule.
- (22,164 − 6,649) / 22,164 = **0.70002** → violates the rule.

So no footprint-internal dot file above 22,163 cells can pass. That covers every file in section 3. The bound is a necessary condition, so it proves the failure but does not prove that every smaller file passes. A file that passes needs a full-registry screen, and the registry is not certified complete (`registry/complete_registry_manifest.json`: `literal_registry_complete: False`, 2,444 rasters, 1,997 unique hashes).

**Why the subset strategy is also blocked.** Removing more dots from GEMSDOE32 gives a subset of it, which is 100 % within 3 px of GEMSDOE32, so it is a duplicate by definition. Any "pruned" variant of the nine files is blocked the same way.

## 5. Why GEMSDOE32 scored 0.2778 (mechanism verified, score not verified)

**Verified geometry** (from the files, not from any receipt):

| Step | Dots removed | Removed dots on a known trace | Removed dots within 1 px of a known trace | Within 2 px | Minimum distance to a known trace |
|---|---|---|---|---|---|
| GEMSDOE25 → 31 | 3,891 | 0 | 3,891 (all) | 3,891 | 1.00 px |

- GEMSDOE32 has **0** dots within 2 px of a known trace. Its nearest dot is 2.24 px away. GEMSDOE36 has the same property.
- The known-trace mask (`labels.tif`, 60,988 cells) is pixel-exact and is **not** in the removed set. These dots sit next to the mask, not on it.

**Mechanism (hypothesis that fits the official rules):** Under the official rule, only new-fault ground truth counts. A dot 1–2 px from a known trace, with no new-fault pixel nearby, is a full false positive. Removing it lowers the false-positive mass and does not lower true-positive credit by much, if the new faults are depleted near known traces. The repo states that depletion as IR-K3-12 ("live new faults are depleted within ~5 px of the catalogue"). That is the repo's claim and has not been independently verified here.

**What this does not show:**
- The score ladder 0.2600 → 0.2708 → 0.2778 is USER-REPORTED. No organizer receipt ties any file hash to any score.
- Whether each removed dot had positive or negative net value depends on new-fault positions, which are not available locally.
- The reported scores are on the public split. The final round is rescored on an expanded label set (problem page), so a public-split score is not a final-round score. This is not excluded.

## 9. What the repo does not yet have (limitations)

1. **Owner decision on the uniqueness rule (blocking).** Options are in [docs/review-2026-10-30.md](review-2026-10-30.md) §6. Until one is chosen in writing, no file above 22,163 cells can be cleared, and every focus file is a duplicate.
2. **Soft probabilities are not testable here.** The official metric accepts per-pixel probabilities. The shared evaluator and writer reject non-binary input (`require_binary_mask`). AGENTS.md says soft support is still discussed in upstream issue [#37](https://github.com/buffedlizard55-lab/GEMSDOE32/issues/37). Testing a soft candidate needs a fix in the shared template, not a private fork.
3. **Complete registry.** `literal_registry_complete: False`. The scan covers 1,991 of 1,997 unique rasters; 6 were skipped.
4. **Organizer copies.** The mirror's `sample_submission.tif` contradicts the page (IR-S8-07). The owner needs to download the official files by hand and supply hashes.
5. **Organizer receipts.** No submission-page receipt links a file hash to a score. Until one exists, every score here stays USER-REPORTED.
6. **Holdout validity.** The repo's holdout withholds catalogue faults. The leaderboard scores new faults that are sometimes within 300 m of known traces (organizer, "Sep 21" post). The repo's own calibration against reported scores is negative for the catalogue proxy (ρ = −0.55, 18 rasters). See [docs/review-2026-10-30.md](review-2026-10-30.md) §8.

## 10. Hypotheses for the next session (untested; none can be promoted yet)

Each candidate must pass, in order: leakage canary → shared holdout → literal uniqueness on the surface and on the final dots. No slot is used before all three pass. Ranking is by expected benefit per cost.

1. **Known-trace depletion prior (binary output).** Keep dots where the new-fault density, estimated from the labels, is above the threshold, and drop the 1–2 px ring around known traces. This is the mechanism behind GEMSDOE32 (section 5). Expected benefit: the same direction as the 25 → 32 step, which is already reported. **But any output derived from GEMSDOE25 or GEMSDOE32 is a subset, so it is a duplicate under the literal rule.** Cost: low. Blocked by item 1 in section 9.
2. **Soft depletion-weighted probabilities.** Output p(x) that decays with distance to known traces instead of a binary dot set. The official metric weights FP by p × [1 − max k], so a soft output is the native form of this idea. Cost: medium, and needs the shared evaluator fixed (section 9, item 2). The rank-correlation test (≤ 0.90) applies to a surface. The 70 % overlap test needs a definition of "support" for a soft surface, and AGENTS.md does not give one. That definition is an owner decision.
3. **Mapping-effort bias check (negative control).** Before trusting any depletion effect, test whether the depletion comes from where experts have mapped, not from geology. A named non-fault mimic is expert-mapping bias around existing traces. Cost: low. It is a control for 1 and 2, not a candidate.
