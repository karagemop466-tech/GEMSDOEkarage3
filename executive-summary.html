What may explain GEMSDOE32's reported result?

Evidence boundary: the value 0.2778 is USER-PROVIDED / UNVERIFIED. The participant-maintained GEMSDOE32 page describes H33-2-B2 as a dotted, spaced pattern related to the GEMSDOE25 d=2.8 design, with dots near the known catalogue removed. Its page does not provide a submission-page receipt that binds the claimed result to the exact TIFF hash. This provenance is a participant-site claim, not independent proof.

Plausible mechanism, not causal proof: the official metric is a distance-weighted Tversky index with a 300 m triangular kernel, `alpha=0.2` for false-positive weighting and `beta=0.8` for false-negative weighting. A spatially spread, lower-redundancy pattern can improve the tradeoff if its dots fall near the newly labeled faults; suppressing dots near already-known faults can shift prediction mass toward unmapped structures. The same edit can also hurt recall if it removes useful predictions. Geometry alone cannot establish which occurred on private test labels.

Can this project claim a result above that value? No. There is no candidate raster, fold-safe holdout, evaluator output, calibration study, or receipt in this checkout. The scientific hypothesis is possible, but neither a higher HOLDOUT-DTI nor a higher organizer score is demonstrated. The only defensible current score estimate is not estimable.

Why the previously reported portal error cannot be cleared here

The competition requires prediction values between zero and one and a GeoTIFF matching the reference CRS, resolution, bounds, and footprint rules. No TIFF bytes were available to inspect, so this review cannot say whether the earlier error came from out-of-range pixels, a data-type/NoData interpretation issue, or another file defect. A future validator must reopen the exact downloadable file, check every in-footprint value for finiteness and range, and compare the stored CRS, shape, transform, and bounds against the actual sample-submission raster.
