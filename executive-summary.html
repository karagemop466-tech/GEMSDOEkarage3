PhD analysis: why GEMSDOE32 h33-h33-2-b2 scored 0.2778, and whether we can beat it

1. Why GEMSDOE32 (0.2778) led the nine focus sites

The GEMSDOE32 submission h33-h33-2-b2-20261004T220000Z-e5eb6e7e-zeros (reported 0.2778) is a pruned subset of the GEMSDOE31 family. Pixel-exact set algebra proves strict nesting:

  • A_32 (37,654 dots) ⊂ A_31 (40,199 dots) ⊂ A_25 = A_30 (44,090 dots) and A_32 ⊂ A_36 (38,854 dots)
  • Every one of the 2,545 pixels in A_31 \ A_32 lies within d ≤ 2.0 px (200 m) of known existing_faults.tif

The distance-weighted Tversky metric (α = 0.2 false-positive penalty, β = 0.8 false-negative penalty, 300 m triangular kernel) penalizes false positives and rewards recovered hidden truth. Those 2,545 removed dots sat within the 300 m kernel collar of already-known catalogue traces, where they received neighbour credit or were pixel-exact masked — so removing them cut the α·FP denominator term by ~509 units at near-zero TP loss. Reported score lifted from 0.2600 → 0.2708 → 0.2778 through successive pruning.

This is a metric-engineering effect, not a geological discovery: the submission removed redundant false positives near known faults, improving the Tversky ratio without adding new hidden-truth recovery. It does not establish that the underlying fault map is more complete or more geothermally relevant.

2. Can we generate a submission scoring higher than 0.2778?

Not yet, and not provably from this holdout. Three structural barriers:

  • Holdout gap: On the same spatial hide-and-recover evaluator (GEMSDOE32-HIDE-RECOVER-v3.0, 22,232 withheld positives), the 0.2778 Champion Rule scores 0.100798 HOLDOUT-DTI. Our best local candidate, karage3-unique-offcat, scores 0.010003 — an order of magnitude below. Neither locally validated file beats the baseline required by the parallel-run protocol before a weekly slot may be spent.
  • Lattice constraint: A registered 206,895-dot calibration lattice (13GEMSDOE r13-lattice-s5) covers 99.87% of the 5,167,373-pixel footprint within 3 px. The literal any-registry 70% rule forces any budget N ≥ 22,164 to overlap the lattice by > 70%. Even N = 20,000 (below the pigeonhole bound) still overlaps 99.1750% empirically. Only ~6,649 pixels are lattice-free, and 98.96% of those are a boundary ring — placing dots there is boundary gaming with no geological signal.
  • No organizer receipt: The 0.2778 figure is USER-REPORTED / UNVERIFIED. No artifact-bound organizer submission receipt binds the file hash to that score. Hidden truth, exact organizer scoring, and final-round labels are unavailable. A holdout proxy is not a leaderboard estimate.

Path to beating 0.2778: a new submission must (a) recover more withheld fault segments than the 0.2778 Champion Rule on the same holdout (target > 0.100798 HOLDOUT-DTI), (b) stay ≤ 70% dot-overlap with every registered raster (rank correlation ≤ 0.90), and (c) pass format validation (float32, [0,1], no NaN inside footprint, exact EPSG:32611 grid). No candidate in this repo currently meets all three.

How to submit to the DrivenData GEMS competition

Read before uploading: no file in this repository is currently cleared for DrivenData submission. Both unique TIFFs fail the same-holdout baseline (0.100798). The steps below describe the submission process; execute only after a selector approves a candidate that beats the holdout baseline.

  1. Download a unique TIF. Choose karage3-unique-offcat-20261029T180337Z-6a8c2368-zeros.tif (or the .zip package). Verify SHA-256: 34cef5830612502ad24dc67314b70b38e636fa8fc644f5997f0456fe7c10c54e.
  2. Verify locally. Run python scripts/check_submission.py FILE.tif --template .cache/gems_data/sample_submission.tif --strict-finite to confirm all 12 format checks pass.
  3. Open DrivenData GEMS (#306). Go to DrivenData DOE GEMS Competition, sign in, navigate to Submissions.
  4. Upload the GeoTIFF. Select the single-band .tif (or single-TIFF .zip). The file is pre-clamped to [0, 1] with no NaN inside the footprint — this prevents the "Predicted values must be in range [0, 1]" portal error.
  5. Enter the note (≤140 characters). Use: Unique off-catalogue detector: 12,000 dots >3px from all focus-site submissions; targets hidden geothermal faults missing from USGS/INGENIOUS catalogue
  6. Save the organizer receipt. Record the submission-page confirmation binding filename, SHA-256, and returned score. Only receipt-backed scores may be labeled ORGANIZER-CONFIRMED.

Note on the portal range error: The DrivenData error "Predicted values must be in range [0, 1]" occurs when a raster contains NaN, Inf, negative, or >1 values. Our -zeros.tif writes 0.0 outside the footprint (all 12,279,160 cells in [0,1], zero NaN). The -nan.tif variant writes NaN outside — matches the historical convention but may trigger the portal range check if NaN is evaluated outside the footprint. Use the -zeros.tif variant for upload.
